What the project found

Canvas hides nothing for you (guide §162a)

Deneb draws Vega on canvas, where a group's opacity does not reach its children. Version B shipped hover cards whose fixed labels — “as a child → now” — stayed on the idle page in Desktop while every SVG render showed them hidden. Every child now carries its own opacity; lint DENEB_HOVER_CHILD_NO_OPACITY catches the shape (controls 3/3; estate sweep 349 visuals, 0 instances).

owner screenshot 15 Oct; test_lint_rules_p28.py

A layout proof must use the host's renderer and the real faces (§162b)

deneb_layout_check.mjs renders on node-canvas and asserts font floor, clearance and containment for every text item, idle and hovered. It lied twice before it told the truth: it read 0 texts and said 0 issues; then it measured bold as regular. It now throws on zero, and fonts come from a fontconfig alias.

S4 runs; promoted to _ENGINE/tools

The cost merge dropped real work (§162j)

Two captures of one transcript path were treated as one session. After a compaction, a later capture is a disjoint segment: P28 lost an hour, and the August control that ‘proved’ the dedupe had encoded the same error. Same path AND overlapping windows now; selftest 15/15; the earlier record corrected.

Assumption tested: an offline render is a sufficient pre-Desktop check

False as stated. Of 6 Deneb defect reports, SVG could show 1, canvas + hover states + a page-scale font floor 4, and 1 (the visual header over the counters) exists only in the host. Necessary, not sufficient.
